# 逐步制作与平台流程

适用于用户明确要求“一步一步”，或主动选择先看文案/样片的任务。直接制作任务采用同样的内部过程，不增加逐轮确认。

## 用途决定叙事

| 用途 | 主要回答 | 资料少时的结构 | 结尾 |
|---|---|---|---|
| 微信个人介绍/朋友圈名片 | 我是怎样的人、看重什么 | 签名钩子 → 一个生活态度或行动主题 → 名字与定位 | 名字＋头像（有则用）＋签名/定位；没有微信号也可完成 |
| 抖音、小红书、B站等内容账号 | 发什么、怎样分享、为什么关注 | 一个问题/主题 → 我是谁 → 1–3个内容方向 → 分享方式 → 关注邀请 | 昵称＋确认的账号ID＋内容价值 |
| 微信视频号 | 用户指定的个人/内容/品牌用途 | 按实际用途选择，不直接套朋友圈个人态度片 | 使用该视频号的实际身份 |
| 品牌或商家 | 提供什么、适合谁、如何了解 | 真实需求 → 产品/服务 → 有证据的差异 → 行动入口 | 品牌名＋真实业务/产品＋用户指定入口 |

这些是选项，不是按平台固定人设。既有主页提供证据，用户的制作目的决定强调哪一部分。

## 分阶段引导

### 1. 资料与定位

先展示2–4项关键信息，省略界面与不打算展示的指标。仅有实质歧义时追问。给2–3个基于现有材料的定位选项，推荐其中一个；如果用户已经明确定位，直接进入文案。

已验证的两类走法：
- 短签名/学习态度 → 个人宣言片：把态度变成学习、尝试、自省等动作，结尾回到真实名字。不要增加学历、职位或成绩。
- 内容简介/尝试过程 → 内容账号片：先问一个观众关心的问题，再介绍真实方向；有年份可以作为卡片信息，没年份就不用时间线。

### 2. 文案与分镜

给完整短文案和时间线，每镜一个主信息。事实来自资料卡；连接句和邀请句明确是创作表达。屏幕文字与配音可共用内容，但配音需在时长内自然读完。

沿用已确定的强度、比例、预算、声音选择。新平台允许风格不同；如果偏好可能只适用于上一条，提出合理方案并说明，不把个人偏好写成永久默认。

在本阶段聚焦内容，避免一次询问风格、字体、配乐、头像、时长十个问题。必要选项集中在当前最影响下一步的一点。

### 3. 动态预览

用户确认文案后，做可播放的约3秒开场，再给身份、中段、结尾关键画面。预览应包含真实账号资料、拟定配色与节拍；写明后续关键画面是分镜还是已完成动画。

同时验证头像是否干净、昵称是否放得下、最长句是否溢出、音量是否合适。预览脚本只导出预览帧段，保持另一账号成片与旧预览独立。

反馈翻译成具体动作：
- “力度更强”：第一帧主体更大、减少慢缓动、改变镜头角度/尺度、用短暂停顿突出重拍；文字落稳后仍可读。
- “更像我/更真诚”：回看签名与内容，调整口吻和素材，而非只换暖色。
- “这版可以/继续”：当前预览获认可，完成全片，不再重新问同一风格。

### 4. 全片、验收、交付

补齐后续运动、完整配乐与收尾；动态预览的3秒音轨不能直接充当完整配乐。最后一屏保留3–5秒识别时间，具体按字数与用途调整。

渲染后用实际MP4检查规格、全帧、主文字、转场、响度，并从成片抽封面。对照 `verification.md`。完成后交可播放成片、封面与说明，不把已验收交付又变成一轮设置问答。

## 保留选择与多账号进度

将每轮选项和回答绑定到阶段。例如“定位A”“文案A”“声音B”分别记录；收到单个 a/b/c 时匹配最近提出的那组，不与早先的选项混淆。更改内容后只重做受影响的文案/镜头。

一个账号完成后用户切换另一个，保留共享的明确约束（例如免费），重新读取当前账号事实。头像、账号、主题、ID与末屏不从上一条继承。输出示例：`out/<project-key>/preview/` 和 `out/<project-key>/final/`。

## 跨 AI 的能力降级

有视觉识别就直接读截图；只有文本能力时请用户任选文字简介或可读链接。无法访问网页时可用用户已给资料继续；无法本地渲染时交付可执行工程与清晰的未完成状态，不声称已生成MP4。TTS是可选分支，不因未登录语音服务阻塞用户已选择的无配音方案。
